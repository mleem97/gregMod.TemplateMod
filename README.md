# gregMod.TemplateMod

A production-oriented reference template for **MelonLoader IL2CPP mods** targeting **Data Center**.

The repository combines the stable patterns used throughout the `gregMod.*`, `gregCore`, plugin, tooling, and deployment repositories while keeping the build reproducible and legally clean.

## Design goals

- one-command local setup from an installed game
- official MelonLoader and Il2CppInterop dependencies from NuGet
- generated game interop assemblies referenced from the local installation
- no committed game, Unity, MelonLoader, or framework binaries
- deterministic .NET 6 x64 builds
- optional `gregCore.dll` integration
- safe MelonLoader lifecycle, Harmony bootstrap, IL2CPP type registration, preferences, logging, and main-thread dispatch
- build, deploy, package, CI, and template-initialization tooling

## Quick start

Create a repository from this template, then initialize it:

```bash
python scripts/init-template.py \
  --name gregMod.Example \
  --author mleem97 \
  --description "Example mod for Data Center"
```

Configure the local game installation:

```bash
python scripts/setup-dev.py --game-dir "/path/to/Data Center"
```

Build:

```bash
./scripts/build.sh
```

PowerShell:

```powershell
./scripts/build.ps1
```

Deploy the built DLL into the game's `Mods` directory:

```bash
python scripts/deploy.py
```

## Dependency model

Public build dependencies are restored from NuGet. The official `LavaGang.MelonLoader` package supplies MelonLoader, HarmonyX, and Il2CppInterop compile-time dependencies.

Game-specific IL2CPP proxy assemblies are generated by MelonLoader after the game has launched once. They remain outside Git and are referenced from:

```text
<Game>/MelonLoader/Il2CppAssemblies
```

The setup script writes the machine-specific path into the gitignored `Directory.Build.local.props`.

See [`docs/DEPENDENCIES.md`](docs/DEPENDENCIES.md) for the complete model.

## Repository structure

```text
src/gregMod.TemplateMod/
├── Core/                 MelonLoader entry point and runtime context
├── Features/             independent feature modules
├── Infrastructure/       logging, preferences, IL2CPP host and dispatch
├── Patches/              Harmony patch registration
├── BuildInfo.cs          mod metadata
└── gregMod.TemplateMod.csproj
scripts/
├── init-template.py      rename and configure a new project
├── setup-dev.py          discover and configure game references
├── verify-env.py         validate the development environment
├── build.ps1 / build.sh  reproducible build wrappers
├── deploy.py             copy the DLL into the game
└── package-release.py    create a distributable ZIP
```

## CI

The default workflow validates scripts, performs a template smoke test, and restores NuGet packages without requiring proprietary game assemblies.

An optional full-build job can be enabled with repository variables/secrets described in [`docs/DEPENDENCIES.md`](docs/DEPENDENCIES.md).
